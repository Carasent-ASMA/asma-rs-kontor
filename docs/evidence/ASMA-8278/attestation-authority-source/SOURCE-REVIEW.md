**Findings**
- **A-01 · Medium (stated-contract level) · destination `-wal` refusal is skipped when the destination main file is zero-length or missing.** `restore.rs:92-94` calls `refuse_nonempty_attestation_ledger(destination)` only when `metadata(destination).len() > 0`; the helper's own nonempty-WAL refusal (`:132-141`) therefore never runs for a 0-byte/absent main file. `classify_destination` then reads a zero-length file as "no Realm" (`:337-341`), and `publish` deletes `-wal`/`-shm` after success (`:263-267`). Reachable chain: in WAL mode a newly created/migrated database can have a 0-byte main file with committed header/schema/rows — including a nonempty key ledger — still in `kontor.db-wal` (the crash artifact the code itself acknowledges at `:242-246` and `:337-340`). An offline restore of an older empty-ledger snapshot then silently publishes over and deletes that WAL state instead of refusing. This contradicts the helper's own comment ("Offline restore must not ignore committed state that still resides in a WAL", `:89-91`) and spec §9.6 (`:324-339`: destination must be checked; nonempty WAL refused, sidecar inventory compared). Mitigating scope: restore is offline and operator-invoked; `publish` removes the residue after success, so the restored file is not corrupted/replayed — the failure is silent rollback/discard of WAL-only pre-restore state, and all nonempty-main-file cases (including WAL beside a nonempty file) are correctly refused by the new tests (`backup_snapshot.rs:105-137,203-285`). Disposition: substantiated source defect in this slice; minimal fix is to test the `-wal`/`-shm` siblings (and the immutable ledger read) unconditionally before classification, independent of main-file length. I do not classify it as a blocker to the whole ledger slice: the ledger CAS/immutability guarantees themselves hold, and empty/main-file restore paths match the spec.
- **A-02 · Info · export now serializes against all writers.** `export_realm` takes the IMMEDIATE writer lock for the whole modeled read/scan (`export.rs:1159`). This is deliberate continuity (a concurrent registration cannot be omitted) and consistent with the contract; noted only as a latency/availability behavior change for modeling exports.
