Progress and consumption between checks

Every check adds a revision. Work done = Jira child issues closed, progressed = issues in progress; consumed = tokens and cost; active work = seat-hours, seats and model responses. Values are the whole four-workstream scope as measured at each check, so they ignore the filters above. The revision picker at the top re-renders every other section as of the selected check, and the KPI tiles and the epic table show the difference against the revision before it. A revision view re-cuts the latest extract at that check's cut; because past transcripts can still be recovered later, an old revision can show slightly more than that check itself reported — the tables below use each check's own captured numbers.

All known token usage — inside vs outside Kontor-style work

Every token still recoverable from the local stores (Codex, Claude Code, OpenCode, GitHub Copilot CLI), not just the selected workstreams. Every token bucket belongs to exactly one category, so the categories add up to the total; a session can span two categories around its Adam takeover. Kontor & Kontor-style = the Kontor workstreams (before and since their Adam), plus every other Kontor-governed seat, role-structured orchestrated seat (LSA/TPM/builder/audit/committee…, parent/child seats, watchdogs) and other Adam/LSA session. Outside = ad-hoc Paseo chats (split by whether they are about Kontor/orchestration) and sessions run directly in a CLI with no Paseo record. Paseo's own records begin , and Claude Code transcripts before are gone — the early numbers are what survives, not what was used. Same data cut as the rest of this report.
